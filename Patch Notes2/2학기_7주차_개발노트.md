# PickPlay 2학기 7주차 개발노트

> 작성일: 2026-10-23 ~  
> 목표: 전역 사운드 제어 UI 도입 및 마스코트 치장 소품 시스템 고도화

## 1. 진행 과제 내역

### Task 1. 전역 사운드 관리자(SoundManager) 구축 및 상단 헤더 사운드 제어 팝오버 UI 연동
- **대상 파일**:
  - 프론트엔드: `public/js/soundManager.js`, `public/games/game.html`, `public/css/common.css`, `public/js/bingo.js`
- **배경 및 목적**:
  1. 기존에는 인게임 BGM과 효과음이 `bingo.js` 내부에 개별 변수(`effectSound`, `eventSound`, `bingoBgm`)로 하드코딩되어 있어, 사용자가 소리를 끄거나 볼륨을 조절할 수 없었음.
  2. 디스코드 음성 통화나 개인 음악을 듣는 유저를 위해 배경음(BGM)과 효과음(SFX)을 개별 제어할 수 있는 글로벌 사운드 컨트롤러 필요.
  3. 브라우저의 오디오 자동재생(Autoplay) 차단 정책을 안전하게 언락하고 유저의 볼륨 설정을 세션 간 보존할 필요성 대두.
- **작업 내용**:
  - **전역 사운드 관리자 모듈 구축 (`soundManager.js`)**:
    - `SoundManager` 싱글톤 객체를 생성하여 BGM(`playBgm`, `stopBgm`) 및 SFX(`playSfx`)를 단일 진입점으로 통합.
    - `localStorage` 연동(`pp_bgm_vol`: 기본 7%, `pp_sfx_vol`: 기본 50%, `pp_sound_muted`: 기본 false)을 통해 브라우저 새로고침(F5) 후에도 볼륨 상태 영구 보존.
    - 유저 첫 인터랙션(클릭, 키다운) 감지 시 오디오 재생을 자동 언락하는 안전장치 탑재.
  - **상단 헤더 팝오버 컨트롤러 UI 마크업 및 스타일 (`game.html`, `common.css`)**:
    - 최상단 헤더를 좌/중/우 3분할 플렉스 구조(`#top-global-header`)로 개편하여 `h1#game-title`을 정중앙에 완벽히 정렬하고, 우측에 `[🔊 사운드]` 글래스모피즘 버튼 안착.
    - 버튼 클릭 시 하단으로 250px 규격의 팝오버 카드(`sound-popover-card`)가 부드럽게 토글되도록 애니메이션 구현.
    - 배경음(BGM) 0~100% 슬라이더, 효과음(SFX) 0~100% 슬라이더, 전체 원클릭 음소거(`btn-mute-all`) 버튼 연동.
    - 팝오버 외부 클릭 시 자동으로 닫히도록 이벤트 바인딩.
  - **인게임 사운드 호출부 마이그레이션 (`bingo.js`)**:
    - `bingo.js`의 구형 `Audio` 객체를 걷어내고 `window.soundManager.playBgm('bingo')`, `playSfx('call')`, `playSfx('event')`로 위임하여 실시간 슬라이더 볼륨 조절이 BGM에 즉각 반영되도록 최적화.
- **검증 결과**:
  - `node -c` 구문 검사 전 파일 에러 0건 통과.
  - 대기실, 게임 대기방, 빙고 인게임 모든 화면에서 상단 헤더 우측 사운드 팝오버가 안정적으로 열리고 닫히는 것을 확인.
  - BGM 슬라이더 조작 시 현재 재생 중인 배경음 크기가 실시간으로 조절되고, 전체 음소거 및 슬라이더 복원 정상 작동 확인.
  - 새로고침(F5) 후에도 `localStorage`에 저장된 볼륨값으로 복원 확인.
- **상태**: 완료 (2026-10-23)

### Task 2. 마스코트(Pick) 치장 소품(파란 캡모자 등) 추가 및 쇼룸 모달 장착 시스템 구축
- **대상 파일**:
  - 에셋/프론트엔드: `public/images/simple_blue_cap.svg`, `public/js/room.js`, `public/games/game.html`, `public/css/common.css`, `public/costume_demo.html`
- **배경 및 목적**:
  1. 기존에는 대기실 [내 캐릭터 꾸미기] 모달에 색상 팔레트만 존재하여, 백엔드와 전역 렌더러에 구축된 `costume` 소품 배열 기능을 유저가 직접 장착·변경할 방법이 없었음.
  2. 사용자가 직접 제작한 신규 에셋(`simple_blue_cap.svg`)을 마스코트 머리 위에 자연스럽게 얹고, 모달에서 실시간으로 소품을 입혀보고 대기실 및 인게임에 즉시 동기화할 수 있는 UI/UX 파이프라인 완성 필요.
- **작업 내용**:
  - **신규 소품 에셋 및 좌표계 정밀 캘리브레이션 (`room.js`)**:
    - `public/images/simple_blue_cap.svg`의 뷰박스(256x160)를 마스코트 캔버스(1254x1254)의 정수리 및 머리 라인(x=441, y=134, w=371, h=232)에 정확히 안착하도록 중첩 SVG 구조로 `MASCOT_ITEMS.cap_blue` 등록.
    - 기존 파티 모자, 황금 왕관, 픽셀 선글라스와 함께 각 아이템별 모달 썸네일 전용 `previewSvg` 정의.
  - **쇼룸 모달 2열 와이드 개편 및 소품 섹션화 (`game.html`, `common.css`)**:
    - `#custom-showroom-modal`을 너비 580px의 2열 와이드 구조로 전면 개편.
    - 좌측: 180px 대형 캐릭터 프리뷰 스테이지와 [완료] 버튼 상시 배치.
    - 우측: `[색상]` / `[소품]` 탭 바 배치 및 소품 탭 내 `머리(모자)`와 `얼굴/눈` 섹션 헤더 분리.
    - 각 부위별 `[미착용(✕)]` 카드 및 각 소품별 3열 반응형 그리드 배치.
    - 소품 카드 호버 및 선택 시 보라색 테두리 글로우 효과(`selected`) 적용.
  - **카테고리별 스마트 토글 및 실시간 동기화 (`room.js`)**:
    - `toggleCostumeItem(itemId)`: 동일 카테고리(모자류)는 자동 교체되며, 다른 카테고리(캡모자 + 선글라스)는 동시 착용이 가능하도록 스마트 토글 로직 구현.
    - `none_head`, `none_eyes`를 통해 특정 부위만 벗거나 전체 해제 가능.
    - 클릭 즉시 좌측 180px 프리뷰 스테이지(`custom-modal-avatar-stage`)에 착용 모습 렌더링.
    - `changeMyCostume`을 통해 `localStorage` 영구 보존 및 소켓 `change costume` 이벤트 브로드캐스트로 대기실 8칸 매트릭스와 인게임 아바타에 실시간 전파.
- **검증 결과**:
  - `node -c public/js/room.js public/js/common.js public/js/soundManager.js` 구문 검사 전 파일 통과 (오류 0건).
  - 모달 내 탭 전환(색상 ↔ 소품) 부드럽게 작동 확인.
  - 파란 캡모자 장착 시 마스코트 머리 위에 자연스럽게 씌워지는 핏 확인.
  - 선글라스 동시 착용 및 모자 교체, 미착용 클릭 시 초기화 동작 정상 확인.
- **상태**: 완료 (2026-10-23)

## 2. 주간 개발 결과 총평
- 7주차 1순위 과제인 전역 사운드 관리자(`SoundManager`)와 헤더 사운드 제어 팝오버 UI를 성공적으로 안착시켜 인게임 오디오 편의성을 대폭 끌어올림.
- 7주차 2순위 과제인 마스코트 치장 소품(파란 캡모자 등) 및 모달 장착/토글 시스템을 구축하여, 유저가 자신만의 캐릭터를 개성 있게 꾸미고 이를 대기실과 전 게임에서 뽐낼 수 있도록 캐릭터 커스터마이징 완결도를 극대화함.
