### Task 1. 방장 설정 모달 다크/라이트 테마 적용
- **대상 파일**: `public/games/game.html`, `public/css/common.css`, `public/js/settingsModal.js`
- **배경 및 문제점**:
  - 메인 대기실 및 게임 화면은 테마 토글(다크/라이트)에 맞춰 CSS 변수가 동적으로 전환되나, 방장 설정 모달(`#settings-modal`) 내부 컨트롤(인풋, 셀렉트박스, 토글 스위치, 라벨)의 스타일이 인라인 및 하드코딩되어 라이트 모드에서 가독성이 떨어지거나 테마 불일치 발생.
- **작업 내용**:
  - `game.html`: `#settings-modal` 하위의 모든 인라인 다크모드 하드코딩 스타일(`background`, `color`, `border`) 및 인라인 이벤트 핸들러(`onmouseover/out`)를 제거하고 전용 BEM 클래스 구조(`settings-modal-*`)로 전환.
  - `common.css`:
    - 모달 프레임(`--modal-bg`, `--surface-glass`, `--border`) 테마 변수 연동.
    - 입력 컨트롤(`.smodal-select`, `.smodal-input`, `.smodal-radio-card`, `.smodal-check-label`, `.smodal-toggle-row`) 전면 테마 토큰 기반 일원화.
    - OS/브라우저 네이티브 드롭다운 이슈 방지를 위해 `option` 태그의 배경 및 글자색을 라이트/다크 전용으로 명시 바인딩.
    - 모달 본문 독립 스크롤바 커스텀 스타일링 적용.
  - `settingsModal.js`: 하드코딩 인라인 색상(`color: #aaa`)을 제거하고 `.smodal-hint`, `.smodal-desc` 클래스를 적용하여 `var(--text-dim)` 동기화.
- **검증 결과**:
  - 브라우저 서브에이전트 실측 검증 완료 (빙고, 라이어, 폭탄 아레나 3개 게임 모달 모두 라이트/다크 모드에서 완벽한 대비 및 폰트 시인성 확보).
  - 모달 열기/닫기, 취소/저장, 라디오/체크박스/토글 상호작용 정상 동작 확인.
- **상태**: 완료 (2026-09-16)

### Task 2. 라이어 게임 신규 서브 모드 [라이어 워드] 규칙 설계 및 구현
- **대상 파일**: `data/liarWordPairs.json`, `sockets/liarSocket.js`, `public/js/liar.js`, `public/js/settingsModal.js`, `public/games/game.html`
- **배경 및 기획**:
  - 기존 라이어 게임은 라이어가 제시어를 아예 모른 채 거짓말을 해야 하므로 첫 턴 진입 장벽이 높음.
  - 라이어에게도 일반 플레이어(시민)와 유사하지만 미세하게 다른 단어(예: 사과 ↔ 배, 지하철 ↔ 버스)를 부여하여, 자신이 라이어인지 모른 채 대화하다가 점차 위화감을 느끼게 하는 심리전 모드 [라이어 워드] 추가.
- **작업 내용**:
  - **단어 페어 데이터셋 신규 구축 (`data/liarWordPairs.json`)**:
    - 음식/과일, 동물, 교통/장소, 일상/물건, 스포츠/문화 등 5개 카테고리에 걸쳐 75개 이상의 엄선된 유사 단어 쌍(Pair) 데이터베이스 작성.
  - **방장 설정 모달 연동 (`settingsModal.js`, `game.html`)**:
    - 라이어 설정 모달 내 '게임 모드' 셀렉트박스(`클래식` / `라이어 워드`) 추가.
    - 모드 변경 시 실시간 설명 문구 동적 전환 연동.
    - `<input type="hidden" id="liar-sub-mode" value="classic">` 동기화 및 `collectSettings` 반환값 확장.
  - **소켓 서버 로직 (`sockets/liarSocket.js`)**:
    - `liarWordPairs.json` 안전 로드 및 카테고리 합집합 반환(`request liar categories`).
    - `setup liar game` 시 `subMode` 저장 및 시스템 안내 메시지 강화.
    - `startRound`: `subMode === 'word'`일 때 페어 데이터 풀에서 무작위 추첨 후 50% 확률로 시민 단어와 라이어 단어를 셔플하여 공정성 확보.
    - 역할 배정(`liar role assigned`): 라이어에게도 라이어 단어를 직접 부여.
    - 최후 변론(`final guess phase`): 라이어가 검거되었을 때 시민들의 진짜 제시어를 맞히도록 유도하는 전용 안내 문구 적용.
    - 결과 처리(`handleRoundEnd`): 결과 패킷에 `subMode`, `liarWord`를 포함하여 브로드캐스트.
  - **클라이언트 UI (`liar.js`)**:
    - 게임 시작 시 `subMode` 전송.
    - 카드 플립: 라이어 워드 모드일 경우 오해를 부르는 '시민' 라벨 및 불필요한 뱃지를 배제하고, 바이올렛 테마(`role-word`) 기반의 카테고리 + 대형 제시어 중심 미니멀 카드로 렌더링하여 심리전 몰입도 극대화.
    - 최후 변론 안내창: 자신이 라이어로 검거되었음을 인지하고 시민 단어를 추리할 수 있도록 직관적 피드백 제공.
    - 결과창: 라운드 종료 및 최종 게임 종료 모달에서 `[진짜 라이어]`, `[시민 단어]`, `[라이어 단어]` 3분할 비교 박스 레이아웃 동적 렌더링.
- **검증 결과**:
  - `node -c` 구문 검사(`liarSocket.js`, `settingsModal.js`, `liar.js`) 전원 통과.
  - 로컬 서버 재기동 후 브라우저 서브에이전트 실측 검증 완료:
    - 방 생성 ➡️ 라이어 게임 진입 ➡️ 설정 모달 오픈 ➡️ [라이어 워드] 선택 시 설명 문구 즉시 전환 및 옵션 동기화 정상 확인.
- **상태**: 완료 (2026-09-21)

### Task 3. 게임 시작 & 결과 발표 몰입감 연출 도입 (3초 카운트다운 & 우승자 폭죽 파티클)

- **배경 및 기획**:

  - 게임 종료 후 최종 우승자 발표 시 시각적 보상을 제공하기 위한 파티클(폭죽) 이펙트 연출 적용.
- **작업 내용**:
  - **독립 프로토타입 제작 및 검증 (`public/preview_effects.html`)**:
    - 버튼 2개(카운트다운 / 우승자 폭죽) 기반 프리뷰 페이지 제작.
    - 블러 제거 및 탄성 스케일다운(`scale 1.6 ➡️ 0.95 ➡️ 1.03`)으로 시인성 극대화.
    - 폭죽 파티클 캔버스 레이어(`z-index: 1000`)를 팝업 앞 최상단으로 올려 시선 집중.
    - 중력 가속도(`0.62`) 및 초기 발사 속도 상향으로 '펑!' 터지는 경쾌한 물리 시뮬레이션 구축.
  - **인게임 정식 이식 (`game.html`, `common.css`, `room.js`)**:
    - `game.html`: `#game-countdown-overlay` 및 `#game-confetti-canvas` 공통 DOM 탑재.
    - `common.css`: 카운트다운 텍스트 글로우/애니메이션 및 캔버스 풀스크린 레이어 스타일 추가.
    - `room.js`: 전역 `window.playStartCountdown(callback)`, `window.triggerConfetti()`, `window.stopConfetti()` 엔진 모듈화. 결과창 닫기 시 메모리 누수 방지 루프 해제(`cancelAnimationFrame`) 연동.
  - **각 게임 연동 (`bingo.js`, `bomb.js`, `liar.js`)**:
    - 게임 최초 시작 시 카운트다운 동시 재생.
    - 게임 종료/최종 승리 모달 오픈 시 팡파르 폭죽 자동 발사 및 닫기 시 즉시 정리.
- **검증 결과**:
  - `node -c` 구문 검사 4개 파일 전원 통과.
  - 브라우저 서브에이전트 인게임 실측 테스트 완료 (카운트다운 및 캔버스 폭죽 정상 작동 확인).
