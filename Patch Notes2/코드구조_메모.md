# PickPlay 코드 구조 메모

> 실제 파일 기준으로 확인한 내용만 적음. 세부 이벤트/데이터 규격은 `Patch Notes/pickplay_data_spec.md` 참고.

---

## 1. 한 줄 요약

Express가 정적 페이지와 단어 테마 API를 서빙하고, 게임 진행은 전부 Socket.IO로 처리한다.
방 상태는 서버 메모리의 `gameRooms` 객체 하나에만 있고, 클라이언트는 받은 상태를 화면에 그리기만 한다.

---

## 2. 서버 구조

```
server.js                    진입점 (Express + HTTP + Socket.IO 생성)
 ├─ routes/themeRoutes.js    /api/themes  (REST, 빙고 테마 단어 CRUD + AI 생성)
 │    └─ controllers/themeController.js, geminiService.js
 │         └─ config/db.js (MySQL 풀) , models/themeModel.js
 └─ sockets/socketManager.js 소켓 접속 시 아래 4개 핸들러 등록, gameRooms 보유
      ├─ commonSocket.js     방 입장/퇴장, 방장, 준비, 채팅, 게임 선택, 재접속
      ├─ bingoSocket.js      빙고 (+ bingoHelpers.js)
      ├─ liarSocket.js       라이어
      ├─ bombSocket.js       폭탄 돌리기
      └─ utils.js            공용 함수 (셔플, 턴 순서, 유저 목록 정렬)
```

- 페이지 라우트는 2개뿐: `/` -> `index.html`, `/room/:roomId` -> `games/game.html`
- 로그인/회원가입은 없다. 닉네임만 입력해서 입장.
- DB(MySQL)는 빙고 테마 단어 저장/캐시 용도. 게임 진행 상태는 DB에 저장하지 않는다.

---

## 3. 핵심 데이터: gameRooms

- 정의 위치: `sockets/socketManager.js`
- 모든 소켓 핸들러에 `(io, socket, gameRooms)`로 같은 객체를 넘겨 공유.
- 방 객체에서 자주 보는 필드 (utils.js 기준): `players`(소켓ID -> 플레이어), `joinOrder`, `hostId`, `status`, `turnOrder`, `turnOrderOption`
- 서버 재시작하면 전부 사라진다 (영구 저장 없음).

---

## 4. 클라이언트 구조

```
public/
 ├─ index.html (+ 로비/방 입장 화면)
 ├─ games/game.html     방 화면 하나에 전부 들어 있음 (페이지 이동 없음)
 │    #lobby-container   대기실 (게임 선택 카드, 플레이어 매트릭스)
 │    #bingo-container
 │    #liar-container
 │    #bomb-container
 │    #result-modal      3개 게임 공통 결과창
 ├─ css/common.css      공통 스타일 (대기실, 결과창 등)
 └─ js/
      room.js           대기실 + 컨테이너 전환 + 플레이어 매트릭스 (commonSocket과 짝)
      bingo.js          빙고 화면 (bingoSocket과 짝)
      liar.js           라이어 화면 (liarSocket과 짝)
      bomb.js           폭탄 화면 (bombSocket과 짝)
      common.js         공통 결과창 모달, 알림
      settingsModal.js  방장 게임 설정 팝업
```

- 화면 전환은 서버가 `game changed` 이벤트를 보내면 `room.js`가 컨테이너의 `hidden-container` 클래스를 바꿔서 처리.

## 5. 서버-클라이언트 짝 (이것만 기억)

| 역할 | 서버 | 클라이언트 |
| :--- | :--- | :--- |
| 방/대기실 | `commonSocket.js` | `room.js` |
| 빙고 | `bingoSocket.js` | `bingo.js` |
| 라이어 | `liarSocket.js` | `liar.js` |
| 폭탄 | `bombSocket.js` | `bomb.js` |
| 결과창 | (각 게임 소켓에서 전송) | `common.js` |

---

## 6. 모든 동작의 공통 흐름

1. 유저 조작 -> 클라이언트 `socket.emit('이벤트', 데이터)`
2. 서버 `socket.on('이벤트')`에서 `gameRooms[roomId]` 수정
3. 서버 `io.to(roomId).emit('결과 이벤트', 데이터)`
4. 클라이언트 `socket.on('결과 이벤트')`에서 화면 갱신

## 7. 작업할 때 어디를 보나

| 하려는 것 | 먼저 볼 파일 |
| :--- | :--- |
| 대기실 UI 수정 | `game.html`(lobby-container), `common.css`, `room.js` |
| 빙고 규칙/버그 | `bingoSocket.js`, `bingoHelpers.js`, `bingo.js` |
| 라이어 규칙/버그 | `liarSocket.js`, `liar.js` |
| 폭탄 규칙/타이머 | `bombSocket.js`, `bomb.js` |
| 방 입장/퇴장/재접속 | `commonSocket.js`, `room.js` |
| 결과창 | `common.js`, `common.css`(#result-modal) |
| 빙고 단어/AI 생성 | `themeController.js`, `geminiService.js`, `themeModel.js` |

## 8. 규모 참고 (코드량이 큰 파일)

`bingo.js`(약 86KB) > `liar.js`(약 58KB) > `room.js`(약 36KB) > `liarSocket.js`(약 30KB) > `bomb.js`, `bingoSocket.js`(약 27~29KB)

처음부터 정독하지 말고, 위 7번 표에서 필요한 파일만 이벤트 이름으로 검색해서 읽는 방식이 효율적.
