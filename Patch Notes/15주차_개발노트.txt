   - liar.css에 메시지 등장 페이드인 애니메이션(`msgFadeIn`) 및 맞춤형 미니멀 스크롤바 디자인 적용

3. [완료] 폭탄 돌리기 / 라이어 게임 플레이어 렌더링 누락 버그 수정

   - `room.js`의 `update user list` 소켓 리스너에서 유저 데이터를 `window.roomPlayers`에 캐싱하여 상시 보존
   - `bomb.js` 및 `liar.js`의 인게임 플레이어 렌더러(`renderBombUsers`, `renderLiarUsers`)가 파라미터가 비어있을 경우 `window.roomPlayers` 전역 데이터를 가져오도록 폴백(Fallback) 구현

     * 4단계: '최종 결과 저장 중...' ➔ '단어판 배치 준비 중...'

6. [완료] 이전 게임 종료 후 신규 인원 난입 시 인게임 렌더링 동기화 오류 수정 (이슈 29)
   - 두 명이 게임을 끝낸 후 대기실에서 세 번째 유저가 입장하여 재시작할 때, 기존 플레이어들의 인게임 클라이언트 변수(currentUsers, currentBombUsers)에 이전 판 2명의 유저 리스트가 캐싱된 채 잔류하는 현상 확인
   - 게임 재시작 시 렌더러 함수에 이 잔류 캐시 변수를 그대로 인자로 주면서 최신 접속 유저인 3인 리스트(window.roomPlayers)가 덮어씌워지지 못해, 기존 유저들에겐 신규 유저가 안 보이고 신규 유저에게만 3명이 정상 노출되던 화면 불일치 버그 발생
   - 이를 차단하기 위해 liar.js 및 bomb.js에서 인게임 렌더러를 호출할 때 잔류 캐시 변수 대신 항시 최신 유저 정보를 들고 있는 window.roomPlayers 전역 스토어를 직접 넘겨주도록 일체 전면 수정 완료

8. [완료] 라이어 게임 최종 결과창 게스트 갇힘 현상 수정 및 UI 일관성 개선 (이슈 30)
   - 라이어 게임 최종 결과창(`FINAL GAME OVER`) 상태에서 확인 완료 버튼 클릭 시, 방장이 확인 및 게임 초기화를 해줄 때까지 게스트들이 결과 확인창 UI에 그대로 갇혀서 빠져나가지 못하는 오류 해결
   - 게스트가 '확인 완료' 버튼을 클릭하면 `confirm result` 소켓 메시지 전송 후 즉시 로컬 UI 및 대기방 화면(`lobby-container`)으로 스스로 복구 처리되도록 개선 완료
   - 방장과 게스트의 결과 확인 버튼을 동일한 텍스트('확인')와 스타일로 일치시키고, 폭탄 돌리기/빙고 게임의 결과창 확인 버튼 문구와도 동일하게 통일하여 UI 일관성 완벽 획득
   - 방장 확인 대기 유도용 게스트용 임시 메시지('⏳ 방장이 게임을 초기화할 때까지 대기해주세요.')를 삭제하여 조잡함을 줄이고 사용성 개선
