■ 수정 1: 결과창 열려있을 때 AI 주제 생성 차단
  파일: public/js/bingo.js
  위치: startGameBtn 클릭 핸들러 최상단
  내용: resultModal.style.display !== 'none' 이면 즉시 return
        → AI API 호출(fetch '/api/themes/generate') 자체가 실행되지 않음
  배경: 결과 확인 대기 중에 방장이 게임 시작 버튼 누르면 AI가 주제를 생성해버리는 버그

■ 수정 2: 한글 자음 입력으로 AI 주제 생성 방지 (이중 방어)
  파일 A: public/js/bingo.js (클라이언트)
    - topic이 /^[ㄱ-ㅎ]+$/ 정규식에 해당하면 API 요청 전에 차단
    - 토스트: "자음만으로는 주제를 생성할 수 없어요..."
  파일 B: controllers/geminiService.js (서버 프롬프트)
    - 프롬프트 맨 앞에 [입력 검증 - 최우선 거부 규칙] 섹션 추가
    - 한글 자음, 알파벳 단일 문자, 무작위 문자 → 즉시 error 반환 지시
  배경: "ㅋ"을 주제로 입력하면 AI가 ㅋ으로 시작하는 단어 39개를 성실하게 뽑아버린 사건

■ 수정 3: 결과창 닫기 버튼이 서버에 확인 완료를 알리지 않던 버그 수정
  파일: public/js/room.js
  위치: closeResultBtn 클릭 핸들러
  내용: socket.emit('confirm result') 추가
  배경: 기존엔 닫기 버튼이 모달만 숨겼고 서버에 confirmedResult=true를 알리지 않음
        → 방장이 게임 시작을 시도해도 서버가 영원히 "아직 확인 중인 유저 있음"으로 차단
        → 방장 입장에서 서버 오류인지 진짜 대기 중인건지 알 수 없었음

■ 수정 4: "결과 확인 중인 플레이어가 있습니다: OOO" 토스트 팝업 제거
  파일: public/js/bingo.js
  위치: socket.on('action failed', ...) 핸들러
  내용: msg.startsWith('아직 결과 확인 중인') 이면 return (토스트 안 띄움)
  배경: 사이드바 플레이어 카드에 "⏳ 결과 확인 중" 배지가 이미 표시되므로
        팝업으로 이름까지 알려주는 건 TMI라고 사용자가 선호하지 않음

게임 종료 → 모든 플레이어 confirmedResult=false 세팅
→ 각 플레이어 결과창 "확인" 클릭 → socket.emit('confirm result')
→ 서버: confirmedResult=true + update user list broadcast
→ 사이드바의 "⏳ 결과 확인 중" 배지 실시간 사라짐
→ 모두 닫으면 방장이 게임 시작 정상 동작
※ 방장이 게임 시작 시도 시 아직 확인 안 한 유저가 있으면 → 조용히 차단 (팝업 없음)
   방장은 사이드바 배지로 시각 확인

현재 메인 프롬프트 (controllers/geminiService.js - generateBingoWords):
  → 충분히 잘 짜여진 프롬프트. 테스트를 많이 거쳐서 안정적.
  → Strict Hierarchy, Early Exit, Self-Correction 조합이 핵심.
  → 건드리지 말 것.

아쉬운 점 3가지와 결론:
  1. Fallback 프롬프트(generateBingoWordsNoGrounding)가 메인보다 허술함
     → 이건 수정할 가치가 있음. 메인 프롬프트 규칙을 그대로 복붙해서 맞춰주면 됨.
     → 아직 미완료 상태.

  2. 하위 카테고리 다양성 규칙 추가 여부
     → 추가하지 않기로 결론.
     → AI가 카테고리 기준을 멋대로 해석, 제3원칙(대중성)과 충돌, 30개 최솟값 달성 어려워짐 등
        리스크가 너무 많고 현재 프롬프트가 이미 안정적이라 건드리면 역효과.

  3. 12글자 제한 vs UI 15글자 제한 불일치
     → 유지하기로 결론.
     → Gemini가 직접 12글자를 권장했고, UI 15글자는 버퍼로 작동 중. 의도된 설계.
